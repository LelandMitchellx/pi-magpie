# 2. 零配置二进制探测天梯与自动流式下载设计

## 状态
已采纳 (Accepted)

## 决策背景与选型
Magpie 本身是一个编译型 Go 二进制工具，没有发布在 npm 上。如果强制要求每个使用者手动配置环境变量 `MAGPIE_PATH` 或安装到全局 PATH，会导致极高的安装与分发失败率。

我们决定在 `MagpieCLI.resolveBinaryPath` 中实现 **5 级探测天梯**，并在完全未命中时自动从 GitHub Releases 流式下载：
1. 插件内置目录：`pi-magpie/bin/magpie(.exe)`
2. 环境变量：`process.env.MAGPIE_PATH`
3. 全局 PATH：探测 `where.exe` / `which`
4. 操作系统常见默认安装路径（如 `%LOCALAPPDATA%\Programs`）
5. **保底机制**：探测当前 OS/Arch，流式拉取最新 GitHub 资产并落盘至插件内置 `bin/`。

## 方案权衡对比
- **要求用户手动配置全局环境变量**：维护成本极高，容易因路径配置错误导致无法运行。*（已否决）*
- **直接将所有平台的二进制随 npm 包打包发布**：导致包体积瞬间暴增数十 MB，且跨架构维护困难。*（已否决）*
- **分级探测 + 懒加载自动下载（本方案）**：日常优先复用已有环境，全新机器一键自愈，兼顾极速与零维护。*（选中）*

## 后续影响与约束
自动下载模块必须处理 GitHub Releases 的多跳 302 重定向，并采用 `.downloading` 临时文件名原子重命名机制，避免写入残缺文件。
