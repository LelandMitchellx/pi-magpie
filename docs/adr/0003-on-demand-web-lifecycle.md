# 3. Web 管理面板按需唤起与会话生命周期设计

## 状态
已采纳 (Accepted)

## 决策背景与选型
Magpie 提供了 Web 仪表盘功能（`magpie web`），但长期常驻一个独立的 Web 进程会额外占用端口 3430 与系统内存。

我们决定采用**按需临时拉起机制**：
- 默认不常驻 Web 进程，只有在用户触发 `/magpie web` 或工具调用 `magpie_open_web` 时才探测端口；
- 若未启动，则在后台以 Detached 模式拉起 `magpie web --addr 127.0.0.1:3430 --no-open`，同时注入固定的管理密钥 `MAGPIE_WEB_KEY`；
- 轮询等待端口就绪后，直接通过系统指令在默认浏览器中打开带登录态的完整 URL (`http://127.0.0.1:3430/?k=...`)。

## 方案权衡对比
- **一直常驻后台运行**：浪费系统资源，增加端口冲突几率。*（已否决）*
- **仅弹出提示让用户去终端手敲**：用户体验割裂。*（已否决）*
- **按需拉起并自动打开浏览器（本方案）**：平时 0 占用，用时一键即达。*（选中）*
