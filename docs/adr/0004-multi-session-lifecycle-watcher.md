# 4. 多会话生命周期共享与最后会话即刻退出机制

## 状态
已更新 (Updated，彻底移除后台独立 Watcher 守护进程，改为信标归零即刻退出)

## 决策背景与演进
原本架构采用了独立的 `node -e` Watcher 后台子进程与 3.5 秒防抖宽限期。但在实际工程与用户体验反馈中：
1. **进程驻留冗余**：独立的 Watcher 守护进程虽然开销小，但仍需在后台多跑一个 Node 进程，增加了跨平台进程管理复杂度；
2. **退出延迟感知**：用户关闭最后一个 Pi 终端后，期望由 Pi 托管的后台 Magpie 能够**立刻、干净利落地结束**，而非在后台默默多活数秒；
3. **多会话冲突防范依然成立**：当多个 Pi 会话（如多标签页或 tmux panes）同时打开时，依然不能误杀仍处于活跃状态的其它 Pi 会话。

## 解决方案
我们将多会话生命周期模型全面精简为**“客户端信标计数 + 最后会话就地即刻销毁”**：

1. **客户端注册与僵死修剪 (Client Session Registry)**：
   - 位于 `~/.pi/agent/magpie-clients/<pid>.json`；
   - 每个 Pi 会话在启动时注册、退出时注销；
   - 每次注销与检查时，通过 `process.kill(pid, 0)` 动态修剪已崩溃或强杀的死条目，杜绝僵尸信标阻碍退出。

2. **最后会话退出即刻销毁 (Instant Teardown on Last Exit)**：
   - 当任意 Pi 触发退出（`session_shutdown` 或进程 exit 信号）时，注销自身信标并扫描剩余活跃 Pi 客户端；
   - **若剩余活跃客户端 > 0**：说明仍有其它 Pi 正在使用网关，保持 Magpie 继续服务；
   - **若剩余活跃客户端 === 0**：检测到当前退出的是集群中的**最后一个 Pi 客户端**，且服务属于 Pi 托管，立即在退出钩子中同步/强力杀死 Magpie 进程树（`killProcessTree`）并清理托管元数据；
   - 彻底废除 `node -e` Watcher 守护子进程，系统架构零额外子进程负担。

3. **外部常驻与托管严格隔离**：
   - 若 Magpie 是用户在外部终端手动启动的（无 `magpie-managed.json` 元数据），Pi 关闭时绝不干预，依然遵循“豁免外部实例”原则。
   - 若用户在 `magpie-config.json` 中配置了 `autoStop: false`，则客户端归零时依然放行常驻。
