# PRD 0001: 核心初衷——随行启动 Magpie 网关服务

## 问题陈述

当开发者使用 Pi Coding Agent 开展日常编码作业时，本地 AI 路由网关（Magpie）是驱动模型推理、分流与降级不可或缺的基础设施。然而，在现有工作流中：
1. 开发者在启动 Pi 前，必须在独立终端手动执行命令拉起 Magpie 服务；
2. 一旦开发者忘记手动启动，Pi 会因无法连接本地网关端口而直接报错中断，开发心智负担沉重；
3. 网关与 Agent 终端的生命周期割裂，缺乏一体化的协同就绪机制。

## 解决方案

在 Pi 扩展初始化与会话开启阶段，自动探测并静默拉起本地 Magpie AI 路由网关服务。开发者只需打开 Pi 终端，所需的本地网关服务即已在后台无感就绪，实现“开箱即用、随行保活”。

## 用户故事

1. 作为一名使用 Pi 的开发者，我希望在 Pi 会话开启时，Magpie 网关能在后台自动启动，以便于我无需手动敲命令就能立刻进入编码状态。
2. 作为一名使用 Pi 的开发者，我希望扩展在尝试启动新服务前，能自动检查本地是否已有运行中的网关，以便于避免端口冲突和冗余进程。
3. 作为一名使用 Pi 的开发者，我希望网关在拉起过程中具备及时的生命周期状态反馈（启动中、启动完成或失败均有明确通知；在复用已有活跃实例时保持静默），以便于我在冷启动等待期内对网关就绪状态拥有明确、确定性的预期。
4. 作为一名使用 Pi 的开发者，我希望后台网关启动失败时能得到温和降级的错误提示，以便于底层网关故障不会导致宿主 Pi 进程直接崩溃闪退。
5. 作为一名使用 Pi 的开发者，我希望网关绑定在稳定的本地默认端口（127.0.0.1:8317），以便于我的 Agent 工具与模型供应商配置能够可靠连接。
6. 作为一名使用 Pi 的开发者，我希望在网关后台启动过程中，Pi 能立即就绪并允许我正常操作终端或加载其他扩展，且在启动中敲击 `/magpie` 时能获得启动中的过渡卡片而非卡死或报错。

## 实现决策

1. **宿主事件生命周期挂载与非阻塞异步解耦**：
   - 依赖宿主扩展运行时的会话启动事件钩子（`session_start`）作为唯一的自动拉起触发源；
   - 严禁在扩展模块顶级导入或同步工厂函数中直接启动子进程，遵循 Pi 扩展生命周期规范；
   - `session_start` 处理器采用非阻塞异步后台任务，**严禁向宿主返回未决 Promise**，立即交还主线程控制权，确保 Pi 毫秒级加载后续插件并渲染 TUI 交互界面。

2. **双重健康度探测（探针机制）**：
   - 在触发启动前，先以非阻塞 HTTP 方式探测网关健康检查端点（`GET /health`）；
   - 若端点返回 200 OK，判定网关已就绪并直接复用，不重复拉起子进程。

3. **独立后台分离子进程**：
   - 启动本地网关可执行文件时，采用子进程分离与解除引用（`detached: true`, `unref()`）模式；
   - 子进程标准输入输出保持独立（`stdio: "ignore"`），并对 Windows 平台隐藏窗口（`windowsHide: true`），确保不会阻塞 Node.js 事件循环。

4. **全生命周期状态透明化与故障降级**：
   - 所有子进程拉起与探活逻辑全程严密包裹在异常捕获内，严禁向宿主抛出未捕获的 Promise Rejection；
   - 在触发新服务拉起前，通过 `onStarting` 钩子向开发者反馈启动中提示（若伴随流式下载则推送实时百分比）；
   - 服务就绪后弹出带有 Web 控制台与免密 Key 的就绪卡片；
   - 若启动超时或报错，降级为清晰明确的 UI 错误提示，绝不影响 Pi 作为代码编辑器的基础功能；
   - 若探测到已有活跃服务运行（如多会话复用），保持静默，绝不产生冗余弹窗干扰。

5. **冷启动过渡态即刻响应 (Fast In-Progress State)**：
   - 暴露 `isStarting(): boolean` 状态谓词；
   - 在网关冷启动探活的过渡窗口期内，用户提前键入 `/magpie` 时，命令立即返回过渡态卡片，既不阻塞等待，亦不误报离线。

## 测试决策

1. **测试边界**：
   - 在高层服务管理接口处建立黑盒测试边界，重点验证健康检查、状态探活与子进程状态转移，不测私有变量。
2. **测试重点**：
   - 验证健康检查在网关未运行与已运行时能够准确返回对应的布尔状态；
   - 验证当服务已经处于健康状态时，连续触发启动操作具有幂等性，且保持静默不产生提示；
   - 验证 `session_start` 回调函数返回 `undefined`，保证非阻塞立即交还控制权；
   - 验证服务拉起时能够按照生命周期正确触发启动中通知、启动完成通知以及失败/异常降级通知；
   - 验证在后台启动中时执行 `/magpie` 指令能够即刻返回启动中过渡卡片。
3. **已有测试参考**：
   - 参考 Node 原生 `--test` 测试套件的标准生命周期设计，保证环境隔离与无残留子进程。

## 范围外声明

1. 自动从互联网下载安装缺失的 Magpie 二进制包（此能力由独立的 PRD 0002 覆盖）。
2. 多会话协同计数、信标管理与退出时的防误杀即刻销毁机制（此能力由独立的 PRD 0003 覆盖）。
3. Web 浏览器的免密访问、图形控制台与额外 Slash 命令交互（此能力由独立的 PRD 0004 覆盖）。
4. 在终端内部提供直接修改 Magpie 路由规则或模型的复杂 CLI 交互。

## 补充备忘

- 本 PRD 是 `pi-magpie` 项目全部演进的唯一“奇点”与初心原点。后续所有新增功能与需求均为本原点的自然衍生或边界防护。
- 无论后续架构如何演进，本初衷所确立的“打开 Pi 即可拥有可用网关”的核心交付价值永不改变。
