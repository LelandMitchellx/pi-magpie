# PRD 0002: 环境保障——零配置二进制探测与流式下载

## 问题陈述

为了践行 PRD 0001 所确立的“打开 Pi 即可拥有可用网关”初衷，前提是宿主机必须具备 Magpie 二进制可执行文件。然而：
1. 新用户往往尚未全局安装 Magpie，手动去 GitHub Releases 下载解压、配置环境变量门槛极高；
2. 跨操作系统（Windows/macOS/Linux）与 CPU 架构（x64/arm64）的资产包命名各异，用户极易下错版本；
3. 如果因环境缺失导致 PRD 0001 无法运转，插件的“开箱即用”承诺就会彻底破产。

## 解决方案

建立 5 级二进制就绪探测天梯（内置目录 -> 环境变量 -> PATH -> 预设路径 -> 自动下载）。在本地完全未命中可执行文件时，自动感知当前操作系统与架构，从官方 GitHub Releases 流式下载匹配的二进制资产并原子落盘至插件内置 `bin/` 目录，全流程零人工干预。

## 用户故事

1. 作为一名未安装 Magpie 的新用户，我希望首次启动 Pi 时插件能自动下载适配的可执行文件，以便于我无需手动翻找 GitHub Releases 或配置 PATH 环境变量。
2. 作为一名拥有自定义 Magpie 构建的进阶用户，我希望插件优先采用我的 `MAGPIE_PATH` 环境变量或本地 PATH，以便于我自己的定制二进制文件优先于自动下载版本。
3. 作为一名跨平台开发者（Windows、macOS 或 Linux，x64 或 ARM64），我希望下载器能准确探测我的操作系统与 CPU 架构，以便于拉取专门为我当前平台编译的资产包。
4. 作为一名网络环境不稳定的用户，我希望下载过程先写入原子临时文件并在校验后再替换目标，以便于网络中断或下载损坏绝不会污染运行环境。
5. 作为一名追求轻量零依赖的开发者，我希望下载逻辑纯原生实现，以便于不向项目中引入庞大臃肿的第三方网络库。

## 实现决策

1. **5 级优先级探测天梯**：
   - 梯级 0：插件内置目录 `pi-magpie/bin/magpie(.exe)`；
   - 梯级 1：显式环境变量 `MAGPIE_PATH`；
   - 梯级 2：系统全局 PATH（通过系统内置 `where.exe` / `which` 解析）；
   - 梯级 3：操作系统常见预设安装目录（如 `%LOCALAPPDATA%\Programs`）；
   - 梯级 4：保底全自动 GitHub Releases 流式下载。

2. **流式重定向与原子性落盘**：
   - 使用 Node.js 原生 `node:https` 处理流式下载，支持跟随 HTTP 301/302 重定向；
   - 资产必须先写入目标目录下的 `.downloading` 临时文件，下载完成并通过完整性校验后，通过原子重命名生效；
   - 在 Unix 平台上自动赋予可执行权限（`chmod 0o755`）。

3. **零运行时外部依赖约束**：
   - 严禁引入任何 npm 外部包（如 `axios`, `node-fetch`, `tar`, `adm-zip` 等），严格保持 `dependencies: {}` 纯度。

## 测试决策

1. **测试边界**：
   - 在解析器抽象接口（`resolveBinaryPath`）与下载状态调度处建立测试缝隙。
2. **测试重点**：
   - 验证当环境变量 `MAGPIE_PATH` 存在时优先采用该路径；
   - 验证平台与架构标识到官方资产命名规则的映射正确性；
   - 验证网络异常时的重试中断与临时文件清理逻辑。

## 范围外声明

1. 自动对现有可执行文件进行静默版本升级（仅在二进制完全缺失时触发下载）。
2. 支持私有镜像源或自建私有分发仓库（保持使用官方 Release 资产源）。

## 补充备忘

- 本需求是 PRD 0001 的底层支撑经线。它保证了无论用户的宿主机环境多么干净，PRD 0001 的核心承诺始终能够 100% 达成。
