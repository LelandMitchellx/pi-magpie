# PRD 0003: 生命闭环——多会话协同与最后会话即刻退出

## 问题陈述

PRD 0001 解决了“开”的问题，但如果没有闭环的“关”，会产生严重的系统污染：
1. **僵尸驻留与端口占用**：用户退出 Pi 终端后，由 Pi 拉起的 Magpie 仍在后台长久驻留，白白耗费内存并锁定 3430 端口；
2. **多终端误杀冲突**：开发者常在多个终端标签页或 tmux 窗口中同时打开多个 Pi。若某一个 Pi 关闭就盲目杀死网关，会导致其它窗口的网络直接瘫痪；
3. **退出的即刻性期望**：用户退出最后一个 Pi 时，期望网关立即干净结束，不接受拖泥带水或后台长达数秒的冗余等待。

## 解决方案

建立基于轻量级文件信标（`magpie-clients/<pid>.json`）的多会话协同器。各 Pi 进程在启动时登记信标、退出时注销信标。退出时动态扫描存活客户端，只要仍有其它活跃 Pi 则保持服务；当检测到自己是最后一个活跃客户端时，立即就地杀灭 Magpie 进程树并清理元数据，实现“随用随在、多窗协同、归零即关”。

## 用户故事

1. 作为一名关闭 Pi 会话的开发者，我希望若当前没有其它打开的 Pi 窗口，Magpie 网关能立即随之结束，以便于我的机器上不留任何僵尸进程或被锁定的端口。
2. 作为一名同时在多个终端标签页中写代码的开发者，我希望关闭其中一个标签页时绝不误杀网关，以便于其它仍在工作的窗口网络请求不受影响。
3. 作为一名关闭最后一个终端标签页的开发者，我希望网关的关闭没有任何冗余延迟，以便于我无需等待防抖倒数，确信进程已被干净回收。
4. 作为一名遭遇 Pi 进程异常崩溃或强杀的用户，我希望后续会话检查时能自动清理僵死的信标文件，以便于死掉的 PID 绝不会阻碍未来的正常关停逻辑。
5. 作为一名在外部独立启动 Magpie 的开发者，我希望 Pi 退出时豁免外部实例，以便于我独立维护的服务绝不会被 Pi 擅自关停。

## 实现决策

1. **客户端信标登记与修剪**：
   - 登记目录位于用户配置目录下的 `magpie-clients/<pid>.json`；
   - 会话启动时登记当前进程 PID，退出时主动注销自身文件；
   - 扫描时通过跨平台 `process.kill(pid, 0)` 探测，若目标 PID 已死亡则直接修剪，杜绝因强制杀死残留的僵死信标。

2. **最后会话即刻就地销毁**：
   - 彻底移除后台独立 Watcher 守护子进程与防抖缓冲期；
   - 在 Pi 的退出钩子（`session_shutdown`, `exit`, `beforeExit`, `SIGINT`, `SIGTERM`）中，先注销自身并扫描剩余存活数；
   - 若存活数为 0 且服务属于 Pi 托管，立即通过系统级进程树杀灭命令强力终止目标进程并清理元数据。

3. **托管状态与外部常驻严格隔离**：
   - 仅当存在有效的受托管元数据文件（`magpie-managed.json`）且启动者归属于 Pi 时才纳入销毁；
   - 若用户在配置文件中显式声明 `autoStop: false`，则放行常驻，不执行杀灭。

## 测试决策

1. **测试边界**：
   - 在协同器顶层接口（`registerClient`, `unregisterClient`, `pruneAndGetActiveClients`, `terminateManagedServiceIfLastClient`）建立黑盒测试边界。
2. **测试重点**：
   - 验证信标注册与正常注销；
   - 验证异常崩溃（模拟不存在的 PID）信标被自动剔除；
   - 验证多客户端并发场景：客户端 A 退出时网关保持存活，客户端 B（最后一个）退出时网关被立即强力销毁。

## 范围外声明

1. 跨机器或远程 SSH 多主机之间的会话生命周期同步（仅聚焦于单机多进程协同）。
2. 在操作系统底层安装 Windows Service 或 systemd 守护脚本。

## 补充备忘

- 本需求构成了 PRD 0001 生命周期的完整闭环。从“随用随在”到“归零即关”，彻底消除了开发者的后顾之忧。
