# PRD 0005: 韧性演进——受控平滑升级与生命周期重绑定

## 问题陈述

在长期使用 Magpie 网关的过程中，官方会持续发布新版本以支持最新的前沿模型协议与路由能力。但在既有架构中，更新操作会导致严重的生命周期脱节故障：
1. **进程裂变与托管断链**：用户在 Web 控制面板内部点击升级重启后，旧 Magpie 进程退役，新进程由 Magpie 自行派生，导致父子进程句柄丢失；
2. **退出销毁短路与孤儿残留**：信标文件记录的旧 PID 失效，所有 Pi 窗口关闭时未能正确清理新进程树，新实例常驻在 3430 端口成为僵尸孤儿；
3. **新会话误判为外部服务**：由于信标被清理，后续打开的 Pi 会话无法重新获得对该网关的主权，只能将其作为“外部常驻服务”只读复用；
4. **文件写入锁冲突**：在 Windows 等操作系统中，直接更新正在运行的可执行文件会被操作系统句柄锁定，无法原地热替换。

## 解决方案

在保持“零 AI Tool 上下文污染”的前提下，扩充极简 Slash 指令体系，引入受控更新（Controlled Upgrade）与自愈重启（Safe Restart）闭环机制。通过 `/magpie upgrade` 与 `/magpie restart` 指令，实现：
1. 先优雅停机释放端口与可执行文件句柄；
2. 优先执行官方原生 `magpie update`，若失败自动降级至内置流式下载器保底；
3. 以受控状态拉起最新版本，自动完成新 PID 的信标持久化与内存句柄重绑定；
4. 沿用历史 WebKey，保障浏览器控制面板免密会话无缝延续。

## 用户故事

1. 作为一名开发者，我希望在终端直接输入 `/magpie upgrade` 就能安全完成 Magpie 的升级，无需手动去 GitHub 下载或手动重启。
2. 作为一名开发者，在执行升级与重启后，我希望新拉起的服务依旧由当前 Pi 会话及其集群信标托管，在退出全部 Pi 终端时能准时自动关闭。
3. 作为一名经常打开多个浏览器的用户，我希望在网关升级重启后，先前打开的 Web 控制台免密链接依然可用，无需重新获取或输入密码。
4. 作为一名遇到网关异常状态的用户，我希望输入 `/magpie restart` 能一键优雅重启当前托管实例并重新建立健康连接。
5. 作为一名在新旧环境下的开发者，我希望升级失败时能有内置下载器自动兜底，并在升级完成后看到清晰的版本状态与 PID 通知。

## 实现决策

1. **统一指令分发**：
   - 保持 `/magpie` 为唯一注册命令，通过参数解析路由到 `upgrade`、`update`、`restart` 等子处理函数；
   - 在无参数调用返回的状态卡片末尾新增子指令操作指引。

2. **先释放后更新的停机原则**：
   - 更新前先检查并主动调用 `stopGateway(true)`，休眠 600ms 等待操作系统句柄释放，彻底解决 Windows 平台下的文件写锁定。

3. **双引擎更新与保底链路**：
   - **优先引擎**：执行解析到的二进制 `magpie update` 原生命令，解析其输出中的 `is the latest` 判定；
   - **兜底引擎**：原生命令超时或失败时，自动调用 `binaryResolver.forceInstallPluginBinary()` 进行原子流式下载落盘。

4. **进程句柄重绑定与密钥继承**：
   - 重新执行 `ensureGateway()`，将新生成的 PID 写入 `magpie-managed.json` 并绑定到 `serviceProcess`；
   - 读取已存在的 `webDashboard.getWebKey()` 作为拉起参数，保持前后会话密钥一致。

## 测试决策

1. **测试边界**：
   - 验证 `runNativeUpdate()` 在最新版本与新版本下的返回结构与 `isLatest` 正确性；
   - 验证 `upgradeAndRestart()` 在服务在线、离线及不同归属（托管 vs 外部）下的平稳过渡；
   - 验证重启后 `getSpawnedWebPid()` 发生变更且信标内容已同步更新；
   - 验证退出 Pi 时 `handleSessionShutdown()` 能正确关闭升级后的新 PID。

## 范围外声明 (Out of Scope)

1. **不监听外部或 Web 内部主动更新**：不注入跨进程 hook 拦截 Magpie Web 面板内部的更新行为，引导用户使用内置 `/magpie upgrade` 完成受控更新。
2. **不增加面向 LLM 的升级 Tool**：严禁向 Agent 暴露 `upgrade_magpie` 等工具，保持 0 上下文污染。

## 补充备忘

- 升级过程中应当向用户提供平滑的 Toast 进度通知（检查中、下载中、拉起中、完成），确保交互透明度。
