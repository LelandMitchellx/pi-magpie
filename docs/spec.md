# 需求规格说明书：pi-magpie 原生扩展 (Spec)

## 问题陈述 (Problem Statement)

开发者在使用 Pi Coding Agent 配合本地部署的 Magpie AI 网关时，存在以下工程痛点：
1. **服务脆弱易断连**：本地 Magpie 未启动或意外退出时，Pi 无法调用底层模型，缺乏后台静默保活机制。
2. **多终端会话冲突与孤儿进程**：用户多开终端时，若某一窗口关闭导致整个网关误杀，会直接中断其他会话；若完全不回收，又会残留孤儿后台进程。
3. **Tool 冗余浪费 Context**：在 LLM 上下文中注入大量用量统计、配额查询和模型切换工具，不仅占用昂贵的上下文窗口，且在命令行查看图表体验远不如 Web。
4. **跨平台安装繁琐**：不同机器环境各异，强依赖用户手动安装配置会导致门槛高。

## 解决方案 (Solution)

构建轻量级、零运行时依赖的纯粹 Pi 原生扩展 (`pi-magpie`)：
- **单进程统一服务架构**：将网关保活与 Web 管理面板收敛为单个后台守护进程，同进程提供 Gateway（默认 `127.0.0.1:8317`）与 Web 控制台（`127.0.0.1:3430`）。
- **多会话协同与防抖守护**：基于客户端会话信标登记与独立 detached Watcher 守护进程，支持多 Pi 终端无缝共享，所有 Pi 关闭后 3.5 秒防抖自动回收后台进程。
- **零 Tool 纯净上下文**：不注入任何 LLM Tool，将所有配置管理权交由可视化 Web 页面与极简 Slash 命令。
- **极简命令联合输出**：输入 `/magpie` 一体化呈现网关健康状态、集群归属、活跃会话与 Web 管理地址（`http://localhost:3430`）。
- **5 级探测与自动下载器**：优先扫描本地路径，未命中时自动从 GitHub Releases 流式下载匹配平台的二进制至插件私有目录，实现真正的零配置安装。

## 用户故事 (User Stories)

1. 作为一名启动 Pi 的开发者，我希望扩展在会话初始化时静默检查网关并在离线时自动在后台拉起，无需手动操作即可直接开始对话。
2. 作为一名开发者，在多终端或 tmux pane 中打开多个 Pi 窗口时，所有窗口能协同复用同一个 Magpie 服务，关闭其中一个窗口绝不影响其他窗口。
3. 作为一名开发者，在所有 Pi 窗口全部关闭后，后台 Magpie 能在短暂防抖宽限期后自动平稳退出，释放系统资源。
4. 作为一名开发者，在 Pi 中输入 `/magpie` 时，能立即查看到清晰的网关状态、集群活跃会话数以及 Web 控制台地址，需要调整模型或额度时直接在浏览器中完成。
5. 作为一名在新环境克隆本项目的开发者，无需手动配置即可开箱即用，自动按需下载对应的 Magpie 可执行文件。

## 核心实现约定

- 纯 TypeScript 构建，编译产物输出至 `dist/index.js`。
- 零运行时依赖（`dependencies: {}`），仅使用 Node.js 原生 API 与 Pi 宿主环境。
- 编译门禁：`npm run build` 全局零类型警告与报错。
